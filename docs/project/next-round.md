# Next round (scheduled for the 8 pm session, 2026-11-21)

!!! note "Historical"
    This is the plan of 2026-11-21 and every item on it was done (releases 0.3.1 to 0.5.0). What is planned now is on the [roadmap](roadmap.md) and the project board.

Work in this order; commit and push after each item, update the GitHub issue and the board (`python3 .local/board-sync.py` if present, else `gh issue edit/close`), test on the simulators first, deploy to the Pi (it is available; the mount is off, so no mount tests), and add anything that needs the owner to `docs/hardware-checklist.md`.

1. **Package upgrade must restart the service (#75).** Look at `packaging/postinst`. On upgrade, restart the service if it was active (`deb-systemd-invoke try-restart`), with the caveat that the unit already flushes frames on stop. Verify on the Pi: install a newer dev build with `dpkg -i`, confirm the process start time changes. Do this first: it makes every later deploy reliable.
2. **Real-data logging for regression fixtures (#35).** A way to record what the tracker and guider saw so real sessions can be replayed offline: an opt-in "Session log" (More tab switch + `PUT /api/session-log`) writing JSON lines per second (status, Sun position/radius/fit, guiding error, pulses sent, mount state, clock) and optionally a downscaled frame every N seconds (PNG, small) into `<storage>/rustflare/logs/<date>/`, with a size cap and rotation. Add a replay test harness (`crates/tracking` tests reading a fixture log) and document the workflow in `docs/development.md`. Keep personal data out of the repo: fixtures committed to git must be synthetic or anonymised (no site coordinates, no device names).
3. **ROI (#14 first part).** Region of interest on the camera: a control (width, height, x/y offset, centred preset 100/50/25 %) in the Camera tab, trait support in `rustflare-core` (`Camera::set_roi`), Player One and ASI drivers where the SDK supports it, simulator support, status carries the ROI, recordings use it (SER header size follows), tracker and optics scale handle a cropped frame (Sun position relative to the full sensor if the SDK reports it). Binning stays out of scope unless trivial. Expected benefit: higher fps for the same USB bandwidth; verify on the Apollo-M MINI on the Pi (fps at full frame vs 50 % ROI) while the owner is away, restoring the original settings afterwards.
4. **Performance audit (#67), second pass.** Measure on the Pi (top -H, with the phone tab closed if possible; otherwise note it). Candidates: share `Arc<Frame>` between preview and recording instead of cloning, reuse JPEG/gray buffers, strided sampling in the tracker's per-frame passes, move the second engine thread's heavy work off the critical path, evaluate `-C target-cpu=cortex-a76` as an optional build flavour (Pi 5 only), measure the malloc tuning before/after. Record before/after numbers in `docs/performance.md`.
5. **Pi hotspot / field networking (#37).** An opt-in access-point mode for use without Wi-Fi: NetworkManager-based (`nmcli`) helper `rustflare-hotspot` (create/enable/disable, SSID and password, status), documented, with a systemd or UI switch only if it is safe: never change the network the owner is currently connected through without an explicit confirmation and a way back (test the helper's dry-run output on the Pi; do NOT bring the hotspot up while the owner depends on the Wi-Fi connection unless it is a time-limited test with an automatic revert). Document the iPhone steps.

Rules that still apply: never move the mount or send mount commands (it is off to save battery); no personal data (site coordinates, device addresses, owner name) in the public repo; do not delete files you did not create; end with a summary comment in the final message and make sure everything is pushed.
